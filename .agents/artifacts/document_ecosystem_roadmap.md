# IBS 문서·전자결재·대외공문 통합 연계 아키텍처 및 구현 로드맵

---

## 1. 추진 배경 및 거버넌스 원칙

IBS 시스템 내 문서는 다음 3가지 서로 다른 법적 효력과 라이프사이클을 갖는 독립 시스템으로 3원화되어 있습니다:
1. **일반 문서 (자료실 / Library)**: 기업 지식 자산, 계약서, 법적 증빙, 기술도면, 사규/서식의 영구 보관소.
2. **전자결재 (의사결정 / Workflow)**: 내부 임직원의 기안, 합의, 검토, 최종 전결 결재 워크플로우.
3. **대외 공문 관리 (공적 커뮤니케이션 / Ledger)**: 관공서, 금융사, 수분양자, 시공사 간의 법적 공문서 발신/수신 대장 및 등기 추적.

이 3대 축의 역할 경계를 명확히 세우고, 상호 간 유기적인 데이터 흐름(Data Pipeline)을 형성하여 **"등록 한 번으로 결재, 공문, 아카이빙이 끊김 없이 연결되는 엔터프라이즈 문서 생태계"**를 구축합니다.

## 2. 3대 도메인 상호 연계 아키텍처

```mermaid
flowchart TB
    subgraph OUTSIDE["대외 이해관계자 (관공서 / 시공사 / 금융기관 / 고객)"]
        EXT_RECV["공문 수신처"]
        EXT_SEND["공문 발신처"]
    end

    subgraph DOCS["1. 일반 문서 자료실 (지식 자산 Library)"]
        D_REG["1. 업무기준(사규)"]
        D_CONT["2. 계약 및 약정서"]
        D_CONF["3. 고시공고·의사록"]
        D_PERM["4. 인허가·등록증"]
        D_ENG["5. 도면·기술도서"]
        D_PR["6. 회사소개(지명원)"]
        D_FORM["7. 표준서식"]
        D_REF["8. 일반·참고자료"]
    end

    subgraph APPROVAL["2. 전자결재 시스템 (내부 의사결정 Workflow)"]
        A_DRAFT["전자결재 기안 (품의/보고/신청)"]
        A_FLOW["결재 라인 (합의 / 검토 / 전결)"]
        A_DONE["최종 승인 (감사 증빙 확정)"]
    end

    subgraph LETTERS["3. 대외 공문 관리 (공적 문서 Ledger)"]
        L_OUT["발송 공문 (Outbound)
        - 공문번호 자동발번
        - 직인 날인 & 시스템 PDF
        - 발송대장/등기 추적"]
        
        L_IN["수신 공문 (Inbound)
        - 접수대장 등록
        - 처리기한 모니터링
        - 담당 부서 지정"]
    end

    %% 연결 관계
    D_FORM -.->|양식 다운로드 후 기안| A_DRAFT
    D_CONT -.->|계약서 원본 첨부| A_DRAFT
    D_PERM -.->|자격/인허가 증빙 첨부| A_DRAFT
    
    A_DRAFT --> A_FLOW --> A_DONE
    
    A_DONE ==>|대외 발송 공문 확정| L_OUT
    L_OUT -->|대외 발송 (이메일/등기)| EXT_RECV
    
    EXT_SEND -->|공문 접수| L_IN
    L_IN ==>|수신공문 처리 품의| A_DRAFT
    
    A_DONE -.->|사규 제개정/최종 계약서 자동 보관| DOCS
```

## 3. 일반 문서 8대 카테고리 재편성안

수신공문 이관 및 모호한 '보고서' 카테고리를 제외하고, 비즈니스 라이프사이클과 법적 중요도에 따라 확정된 8대 카테고리입니다.

| 순서 | 카테고리 명 | 영문 코드 | 포함 대상 문서 | 실무상 특징 및 역할 |
| :---: | :--- | :--- | :--- | :--- |
| **1** | **업무기준(규정)** | `STANDARD` | 취업규칙, 인사규정, 위임전결규정, 회계규정, 안전보건관리 지침 | 사내 '헌법'이자 대원칙. 자료실 1번에 위치하여 기준점 제공 |
| **2** | **계약 및 약정서** | `CONTRACT` | 공사도급계약, 토지매매계약, 설계/감리/PM 용역계약, PF 대출약정서 | 사업의 권리·의무를 규정하는 최우선 법률 문서 (사용 빈도 최상) |
| **3** | **고시공고·의사록** | `ANNOUNCE` | 입찰공고, 총회소집공고, 분양공고, 이사회/주총/조합총회 의사록(공증본) | 사업 절차의 적법성을 증빙하는 법적 공고 및 회의체 결의 문서 |
| **4** | **인허가·등록증** | `LICENSE` | 사업자등록증, 법인등기부, 건설/개발업등록증, 건축허가서, 착공/준공필증, 통장사본, 완납증명 | 행정청 발급 자격/허가 및 상시 대외 제출용 패키지 일원화 |
| **5** | **도면·기술도서** | `DRAWING` | 건축/토목/전기 도면(CAD/PDF), 지질조사보고서, 구조계산서, 시방서 | 설계 및 시공 현장 필수 엔지니어링 기술 데이터 |
| **6** | **회사 소개(지명원)** | `PR_INTRO` | 회사 소개서, 공식 지명원, 기업 브로셔, 시공/시행 실적표 | 입찰/제안/PF 심사 시 4번 등록증과 함께 쌍으로 제출되는 대표 홍보물 |
| **7** | **표준 서식** | `FORM` | 표준 계약서식, 기안 양식, 각종 사내 신청서/확인서 표준 템플릿 | 임직원이 문서를 작성할 때 사용하는 공식 표준 템플릿 |
| **8** | **일반·참고자료** | `REFERENCE` | 시장조사(F/S)·감정평가 자료, 관련 법령집, 부동산/건설 통계 및 세미나 자료 | 기타 사내 지식 아카이브 |

## 4. 도메인 간 4대 핵심 연계 시나리오

### 시나리오 1: 표준 서식 활용 ➔ 전자결재 기안 ➔ 완료 문서 자동 아카이빙
- **Flow**:
  1. 임직원이 일반 문서의 `표준 서식`에서 최신 계약서/신청서 서식 다운로드.
  2. 전자결재에서 해당 서식을 첨부하거나 등록된 폼으로 기안 작성 및 결재 진행.
  3. 사규 제·개정 품의, 중요 계약 체결 품의가 최종 승인(`approved`)되면, 옵션 선택에 따라 일반 문서의 `업무기준(규정)` 또는 `계약 및 약정서` 카테고리로 확정본 PDF가 자동 등재.

### 시나리오 2: 발송 공문 기안 ➔ 전자결재 ➔ 직인 날인 및 대장 발송 (기구현 고도화)
- **Flow**:
  1. 대외 공문 관리에서 공문 작성(수신처, 본문, 인장 선택) 후 [전자결재 상신] 클릭.
  2. 연동 결재선(`RouteTemplate`)에 따라 승인 진행 (기안 회수 시 공문 상태 자동 동기화).
  3. 최종 승인 즉시 법인직인 전자 날인 및 시스템 PDF 자동 생성.
  4. 발송 담당자가 이메일/등기 발송 후 발송 대장(`dispatched_at`, `tracking_number`) 업데이트.

### 시나리오 3: 수신 공문 접수 ➔ 전자결재(대응 보고) ➔ 발송 공문 회신 연계 (신규)
- **Flow**:
  1. 관공서/시공사로부터 공문 수신 시, 대외 공문 관리 `수신 공문(Inbound)`에 접수 등록 (문서번호, 접수일, 회신요청기한, 첨부파일).
  2. 수신 상세 화면에서 **[처리 보고 전자결재 상신]** 버튼 원클릭 ➔ 수신 공문이 자동 첨부된 결재 기안창 오픈.
  3. 내부 방침 결재 완료 후 회신이 필요한 경우, 결재 문서에서 **[회신 공문 작성]** 버튼을 통해 발송 공문 작성 화면으로 원클릭 전환(수신 공문 참조 번호 자동 연결).

### 시나리오 4: 일반 문서 자산 ➔ 대외 공문 붙임 서류 원클릭 불러오기 (신규)
- **Flow**:
  1. 발송 공문 작성 시 붙임(첨부파일) 등록 영역에서 로컬 파일 업로드 외에 **[자료실에서 선택]** 모달 제공.
  2. 일반 문서의 `인허가·등록증`(사업자등록증, 사용승인서 등)이나 `회사소개(지명원)`를 검색하여 클릭 한 번으로 공문 붙임 서류로 자동 바인딩.

## 5. 단계별 구현 로드맵 (Roadmap)

### Phase 1: 일반 문서 카테고리 개편 및 기존 데이터 정리 (단기 - 1~2주)
- **백엔드**:
  - `docs.models.Category`에 8대 신규 카테고리 정의 및 정렬 순서(`order: 1~8`) 반영.
  - 기존 카테고리 매핑 데이터 마이그레이션:
    - 기존 `수신공문` 데이터 ➔ 대외 공문 관리의 `Inbound` 레코드로 데이터 이전.
    - 기존 `보고서`, `기타` 데이터 ➔ 내용에 따라 `일반·참고자료` 또는 관련 프로젝트로 재배치.
- **프론트엔드**:
  - `GeneralDocList.vue` 카테고리 탭/셀렉터 신규 8대 순서 적용.
  - 카테고리별 아이콘 및 배지 색상 표준화.

### Phase 2: 대외 공문 관리(수신 공문) 고도화 (중기 - 2~3주)
- **기능 구축**:
  - 수신 공문(`Inbound`) 접수 폼 및 상세 화면 완성 (발신처, 접수일자, 접수번호, 회신기한, 첨부파일).
  - 마감 임박 수신 공문 D-Day 알림 및 현황 대시보드 칩 제공.
- **연계 구축**:
  - 수신 공문 상세 ➔ **[대응 품의 상신]** 버튼 연동 (전자결재 기안 연계).

### Phase 3: 전자결재 ➔ 일반 문서 / 대외 공문 간 파이프라인 연계 (중기 - 3~4주)
- **결재 후 아카이빙 연계**:
  - 전자결재 문서 유형(DocumentType) 메타데이터에 `target_doc_category` 필드 추가.
  - 특정 문서(사규, 중요 계약) 승인 시 일반 문서 자료실 자동 등재 트리거 구현.
- **수신 공문 ➔ 결재 ➔ 발송 공문 양방향 링크**:
  - `ApprovalDocument` 모델에 `related_inbound_letter` 외래키 추가.
  - `OfficialLetter` 모델에 `parent_inbound_letter`(답신 대상 수신공문) 연결 필드 추가하여 공문 왕복 추적 체계 구축.

### Phase 4: 크로스 도메인 자산 연동 및 검색 고도화 (장기)
- **공문 첨부 연계**:
  - 공문 작성 시 `인허가·등록증`, `지명원` 라이브러리 직접 선택 팝업 제공.
- **통합 검색 (Global Document Search)**:
  - 일반 문서 + 결재 완료 문서 + 공문 대장을 관통하는 통합 키워드 검색 엔진 구축.
