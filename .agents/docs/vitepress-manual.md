# 사용자 매뉴얼 (VitePress) 작성 규칙

사용자 매뉴얼 소스는 `app/vue/docs/`에 위치하며, `app/vue/` 디렉토리에서 아래 명령으로 확인 및 빌드할 수 있습니다.

```bash
pnpm docs:dev    # 로컬 문서 개발 서버
pnpm docs:build  # VitePress 정적 사이트 빌드
```

매뉴얼 문서를 추가하거나 수정할 때는 아래 원칙을 반드시 준수합니다.

## 1. 신입사원 눈높이의 친절하고 실용적인 사용자 친화성

* 신입사원이나 처음 시스템을 접하는 임직원이 매뉴얼을 보고 실제 업무에 즉시 적용할 수 있도록 친절하고 알기 쉽게 작성합니다.
* 개발자/백엔드 관점(Django 모델명, DB 테이블명, 내부 엔진 명칭 등)을 배제하고, 실제 화면 UI에 표시되는 한글 레이블과 버튼 명칭을 기준으로 설명합니다.
* 단순 기능 나열에 그치지 않고 **"누가, 언제, 왜 이 기능을 쓰며, 화면의 어디를 클릭해야 하는지"** 실제 사용에 직접적인 도움이 되는 실무 가이드와 팁(Tip)을 제공합니다.

## 2. 실제 화면 이미지 플레이스홀더 및 등록 가이드

* 시각적 이해가 필요한 핵심 화면이나 복잡한 입력 폼은 매뉴얼 내에 **실제 화면 이미지 섹션(플레이스홀더)**을 명시적으로 구성합니다.
* 관리자가 향후 실제 시스템 UI 캡처본을 손쉽게 등록·교체할 수 있도록 아래 가이드 블록 형식으로 표준화합니다.

```markdown
::: tip 📸 실제 화면 안내
![화면 설명](./images/화면명.png)
*관리자 참고: 해당 화면의 실제 캡처 이미지를 `./images/화면명.png` 경로에 등록해 주세요.*
:::
```

* 이미지가 아직 준비되지 않은 경우에도 해당 섹션을 통해 사용자에게 UI 위치와 구조를 직관적으로 파악할 수 있는 기준을 제시합니다.

## 3. 맥락에 부합하는 자연스러운 실무 용어 사용

* 시스템 단위(`워크스페이스`, `프로젝트`)의 도메인 개념은 엄격히 준수하되, `"현장 사진 첨부"`, `"현장 외근/실사"`와 같이 실제 오프라인의 물리적 작업 현장을 명확히 지칭할 때는 억지스러운 치환을 지양하고 자연스러운 실무 표현을 사용합니다.

## 4. `##` (h2) 요소 직전 구분선 (`---`) 사용 엄금

* VitePress 기본 CSS 테마에서 `h2` 요소 상단에 `border-top` 구분선이 자동으로 렌더링됩니다.
* `##` 직전에 수동으로 `---` 구분선을 추가하면 선이 이중으로 중복 표출되므로 **`##` 바로 앞에는 절대로 `---`를 작성하지 않습니다.**
